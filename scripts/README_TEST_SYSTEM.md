# PyTest + Cypress Integration System

This document describes the integrated test execution system that runs ALL PyTests before Cypress tests and generates comprehensive failure reports.

## 🎯 Overview

The system ensures that:
1. **ALL PyTests run first** - No `--maxfail` limiting
2. **Failure summaries are always generated** - Even when tests fail
3. **Cypress tests run after PyTest** - Regardless of PyTest results
4. **Full artifacts are produced** - JUnit XML, raw output, and markdown summary

## 🏗️ Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    npm run test:all                          │
│                (run_all_tests.mjs)                           │
└──────────────┬──────────────────────────────────────────────┘
               │
               ├──► 1. Run PyTests (run_pytests_and_summarize.mjs)
               │    ├─► Execute: python -m pytest --maxfail=0 --junitxml=...
               │    ├─► Generate: reports/pytest/junit.xml
               │    ├─► Generate: reports/pytest/output.txt
               │    └─► Generate: reports/pytest/summary.md
               │
               └──► 2. Run Cypress Tests (with CC_SKIP_PYTEST=1)
                    └─► npx cypress run
                         └─► before:run hook checks env var
                              └─► Skips pytest (already ran)
```

### Two Execution Paths

**Path 1: `npm run test:all` (Wrapper)**
- PyTest runs ONCE in wrapper
- Sets `CC_SKIP_PYTEST=1` environment variable
- Cypress hook detects env var and skips pytest
- Result: PyTest runs exactly once

**Path 2: `npx cypress run` (Direct)**
- No env var set
- Cypress `before:run` hook executes pytest
- Result: PyTest runs once (via hook)
```

## 📁 Files Created

### Scripts
- `scripts/run_pytests_and_summarize.mjs` - Runs pytest and generates reports

## 🚀 Usage

### Run All Tests (PyTest + Cypress)
```bash

```

### Run Only PyTests
```bash

```

### Run Only Cypress (with PyTest hook)
```bash

```

## 📊 PyTest Command

The exact pytest command used:
```bash
python -m pytest --maxfail=0 --junitxml=reports/pytest/junit.xml --tb=short -v
```

**Key Parameters:**
- `--maxfail=0` - **Never stop early**, run ALL tests regardless of failures
- `--junitxml=...` - Produces JUnit XML for CI integration
- `--tb=short` - Shorter traceback format
- `-v` - Verbose output

## 🛡️ Stale Artifact Protection

The system prevents "stale success" by cleaning old artifacts before each run.

### Artifact Cleanup Process

**At the start of every pytest run:**

1. Create `reports/pytest/` directory (if needed)
2. Delete existing artifacts (if present):
   - `reports/pytest/junit.xml`
   - `reports/pytest/output.txt`
   - `reports/pytest/summary.md`
3. Run pytest and generate fresh artifacts

**Why this matters:**

- Prevents reading old `junit.xml` from previous runs
- Ensures CI failure if pytest crashes before writing new artifacts
- Guarantees every report reflects the current test run

### Missing JUnit XML Handling

**If pytest completes but `junit.xml` is missing:**

- Likely causes: collection crash, import error, fatal pytest error
- System generates special summary with:
  - Clear warning message
  - Last 80 lines of pytest output for quick diagnosis
  - Recommendations for troubleshooting

**Example missing JUnit summary:**

```markdown

## 🔒 Preventing Double PyTest Execution

The system uses an environment variable to prevent pytest from running twice:

### Environment Variable: `CC_SKIP_PYTEST`

**When set to `"1"`:**
- Cypress `before:run` hook skips pytest execution
- Logs: `[test-system] Skipping pytest in Cypress (already ran in wrapper).`

**Behavior by execution path:**

| Command | PyTest Runs | CC_SKIP_PYTEST | Hook Behavior |
|---------|-------------|----------------|---------------|
| `npm run test:all` | Once (in wrapper) | Set to `"1"` | Skips pytest |
| `npx cypress run` | Once (in hook) | Not set | Runs pytest |
| `npm run pytest:all` | Once | N/A | No Cypress |

**Implementation:**

In `scripts/run_all_tests.mjs`:
```javascript
execSync('npx cypress run', {
  env: {
    ...process.env,
    CC_SKIP_PYTEST: '1',  // ← Tells Cypress to skip pytest
  },
});
```

In `cypress.config.js`:
```javascript
on('before:run', async () => {
  if (process.env.CC_SKIP_PYTEST === '1') {
    console.log('[test-system] Skipping pytest in Cypress (already ran in wrapper).');
    return;  // ← Skip pytest execution
  }
  // Otherwise run pytest as normal
});
```

## ⚙️ How It Works

### 1. Direct Execution (`npm run test:all`)
- `run_all_tests.mjs` runs pytest script
- **Pytest script cleans stale artifacts first**
- Captures pytest exit status from JUnit XML
- **If JUnit missing/malformed, treats pytest as FAILED**
- Sets `CC_SKIP_PYTEST=1` environment variable
- Runs cypress with env var (hook skips pytest)
- Exits with code 1 if EITHER failed

### 2. Cypress Hook Execution (`npx cypress run`)
- `cypress.config.js` defines `before:run` hook
- Hook checks for `CC_SKIP_PYTEST` env var
- If not set, executes `run_pytests_and_summarize.mjs`
- **Pytest script cleans stale artifacts first**
- PyTest script ALWAYS exits 0 (to allow Cypress to run)
- Cypress proceeds normally

### 3. PyTest Script (`run_pytests_and_summarize.mjs`)
- Creates `reports/pytest/` directory
- **Deletes old junit.xml, output.txt, summary.md**
- Executes pytest command with `--maxfail=0`
- Captures output even on failure
- **Checks if junit.xml was generated**
- If missing: generates special summary with last 80 lines
- If present: parses JUnit XML normally
- Generates markdown summary (includes command executed)
- ALWAYS exits 0

### 4. Wrapper CI-Safe Failure Detection (`run_all_tests.mjs`)
- Reads `reports/pytest/junit.xml` if it exists
- **If missing:** marks pytest as FAILED, logs clear message
- **If malformed:** marks pytest as FAILED (missing required attributes)
- **If parsing error:** marks pytest as FAILED
- If valid: checks failures/errors counts
- Always runs Cypress regardless
- Exits 1 if pytest OR cypress failed

## 🚨 Important Notes

1. **PyTest never blocks Cypress** - The pytest script always exits 0
2. **CI fails on any failure** - `run_all_tests.mjs` returns 1 if either fails
3. **Reports are gitignored** - Don't commit generated reports
4. **Summary truncates long output** - First 30 lines per error
5. **No test fixes** - System only reports, never modifies tests
